# Books Analytics

**Books Analytics** — приложение на Python для сбора и анализа информации о книгах из открытого учебного каталога [Books to Scrape](https://books.toscrape.com/).

Проект реализует асинхронный обход страниц каталога, извлечение данных из HTML, сохранение результатов в JSON и построение статистических отчётов. Повторные запуски позволяют обновлять сведения о ранее сохранённых книгах без создания дубликатов.

Приложение разработано как учебный проект с акцентом на модульную архитектуру, обработку ошибок, тестирование и воспроизводимый запуск.

## Возможности

- Асинхронная загрузка страниц с использованием `aiohttp`.
- Ограничение количества одновременных HTTP-запросов.
- Повторные попытки загрузки при временных сетевых ошибках.
- Извлечение названия, цены, рейтинга, наличия и ссылки на книгу.
- Автоматическое определение количества страниц каталога.
- Сохранение результатов в JSON.
- Идентификация книг по SHA-256 от их URL.
- Обновление существующих записей без дублирования.
- Фильтрация по цене и рейтингу.
- Расчёт статистики с использованием `pandas`.
- Построение графиков с помощью `matplotlib`.
- Логирование основных этапов работы.
- Возможность периодического запуска.
- Запуск в Docker и Docker Compose.
- Автоматизированное тестирование с контролем покрытия кода.

## Установка и запуск

### Требования

Для локального запуска необходимы Python 3.12 и доступ к интернету.

Для контейнерного запуска требуется Docker с поддержкой Docker Compose.

### Локальный запуск

Клонируйте репозиторий:

```bash
git clone https://github.com/A1exWork/books-analytics.git
cd books-analytics
```

Создайте виртуальное окружение:

```powershell
python -m venv .venv
```

Активируйте его в Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Установите зависимости:

```powershell
python -m pip install -r requirements.txt
```

Запустите приложение:

```powershell
python main.py
```

Программа загружает каталог, сохраняет полученные данные и выполняет аналитическую обработку.

### Запуск через Docker Compose

При установленном и запущенном Docker выполните:

```bash
docker compose up --build
```

Docker Compose собирает образ приложения и запускает контейнер. Каталоги `data`, `logs` и `reports` подключены к контейнеру как локальные тома, поэтому результаты сохраняются на компьютере после завершения процесса.

При необходимости повторного запуска используется та же команда.

### Запуск из Visual Studio Code

В репозитории предусмотрена задача `.vscode/tasks.json`.

Чтобы запустить приложение:

1. Откройте папку проекта в Visual Studio Code.
2. Убедитесь, что Docker запущен.
3. Нажмите `Ctrl + Shift + B`.

Редактор выполнит команду `docker compose up --build` и покажет журнал работы приложения во встроенном терминале.

## Сбор и хранение данных

Источником данных служит [Books to Scrape](https://books.toscrape.com/) — сайт, предназначенный для практики веб-скрейпинга.

Для каждой книги сохраняются следующие сведения:

| Поле | Описание |
|---|---|
| `id` | SHA-256 от URL книги |
| `title` | Название |
| `price` | Цена в фунтах стерлингов |
| `rating` | Рейтинг от 1 до 5 |
| `availability` | Информация о наличии |
| `url` | Ссылка на страницу книги |

Данные записываются в `data/books.json`.

При повторном запуске приложение сравнивает новые сведения с сохранёнными записями. Если книга уже присутствует и её данные не изменились, дополнительная запись не создаётся. Если сведения изменились, существующая запись обновляется.

Запись JSON выполняется через временный файл с последующей заменой целевого файла. Такой подход снижает риск повреждения сохранённых данных при прерывании операции записи.

## Аналитика

После сбора данных приложение рассчитывает:

- Общее количество обработанных книг.
- Среднюю цену.
- Медианную цену.
- Количество книг с каждым рейтингом.
- Среднюю цену книг для каждого рейтинга.

В каталоге `reports` формируются два изображения:

| Файл | Содержимое |
|---|---|
| `prices.png` | Распределение цен |
| `ratings.png` | Распределение рейтингов |

### Пример результата

При одном из запусков приложение обработало 1 000 книг с 50 страниц каталога.

| Показатель | Значение |
|---|---:|
| Количество книг | 1 000 |
| Количество страниц | 50 |
| Средняя цена | £35.07 |
| Медианная цена | £35.98 |

Эти значения приведены как пример фактического запуска. При изменении данных источника результаты могут отличаться.

## Настройка

Основные параметры приложения определены в `app/config.py`.

| Параметр | Назначение |
|---|---|
| `BASE_URL` | Адрес исходного каталога |
| `REQUEST_TIMEOUT` | Тайм-аут HTTP-запроса |
| `CONCURRENT_REQUESTS` | Ограничение параллельных запросов |
| `MAX_RETRIES` | Максимальное количество попыток загрузки |
| `MIN_PRICE` | Минимальная цена для фильтрации |
| `MAX_PRICE` | Максимальная цена для фильтрации |
| `MIN_RATING` | Минимальный рейтинг |
| `PARSE_INTERVAL_MINUTES` | Интервал периодического запуска |

Для параметров фильтрации значение `None` означает отсутствие соответствующего ограничения.

## Тестирование

Для автоматизированного тестирования используется `pytest`.

Тесты охватывают:

- Извлечение данных из HTML.
- Обработку пустых страниц и неизвестных рейтингов.
- Успешную загрузку страниц.
- Повторные HTTP-запросы при ошибках.
- Обработку ошибок после исчерпания попыток.
- Определение количества страниц каталога.
- Сохранение книг и предотвращение дубликатов.
- Обновление существующих записей.
- Фильтрацию по цене и рейтингу.
- Расчёт статистики и создание графиков.

При тестировании сетевой логики используются имитации HTTP-ответов. Это позволяет проверять поведение парсера без обращения к внешнему сайту.

Установите инструменты тестирования:

```powershell
python -m pip install pytest pytest-cov
```

Запустите тесты:

```powershell
python -m pytest
```

Для отдельного просмотра покрытия:

```powershell
python -m pytest --cov=app --cov-report=term-missing
```

В ходе разработки достигнуто **86% покрытия кода**.

Минимально допустимый уровень установлен на **80%** в `pytest.ini`. При снижении покрытия ниже этого порога проверка завершается с ошибкой.

Покрытие отражает долю строк, выполненных при тестировании, и само по себе не гарантирует отсутствия ошибок или уязвимостей.

## Логирование и обработка ошибок

Приложение записывает сведения о ходе выполнения, включая начало сбора данных, количество обработанных книг, результаты сохранения и завершение аналитики.

При временных сетевых ошибках предусмотрены повторные попытки загрузки. После исчерпания установленного количества попыток ошибка передаётся вызывающему коду.

Журнал приложения сохраняется в каталоге `logs`.

## Безопасность и ограничения

Проект предназначен для учебного использования и не является промышленной системой сбора данных.

При работе с ним следует учитывать следующие особенности:

- Приложение выполняет HTTP-запросы к внешнему источнику и зависит от его доступности и структуры HTML.
- Изменения разметки сайта могут потребовать корректировки парсера.
- Данные из внешнего источника не следует считать полностью достоверными.
- Перед использованием другого сайта необходимо ознакомиться с его правилами доступа и ограничениями на автоматизированные запросы.
- В репозиторий не следует добавлять пароли, токены доступа, приватные ключи и другие секреты.
- Локальные данные, журналы, результаты анализа и виртуальное окружение исключены из обычного отслеживания Git через `.gitignore`.
- Настройки `.gitignore` не удаляют конфиденциальную информацию из ранее созданных коммитов.
- Зависимости и Docker-образ необходимо периодически обновлять с учётом исправлений безопасности.

Приложение не предоставляет публичный веб-интерфейс или API для удалённого управления.
